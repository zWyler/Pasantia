# SPRINT 0 — PLANIFICACIÓN

## 1. Objetivo del Sprint

Definir las bases funcionales, técnicas y organizativas necesarias para iniciar el desarrollo de StudyHub, estableciendo los requisitos iniciales, la arquitectura tecnológica, las herramientas de trabajo y la estructura del proyecto.

## 2. Caso de usuario — Estudiante

**Actor:** Estudiante.

**Situación:**

Un estudiante tiene varias materias y debe realizar diferentes tareas con fechas de entrega, prioridades y estados. Actualmente, puede tener esta información distribuida en diferentes lugares, lo que dificulta llevar un control de sus actividades.

**Necesidad:**

Contar con un lugar donde pueda organizar y consultar fácilmente toda su información académica.

**Solución propuesta:**

StudyHub permitirá al estudiante registrar sus materias y tareas, establecer fechas de entrega y prioridades, consultar sus actividades mediante un calendario, recibir notificaciones y visualizar su progreso académico.

**Resultado esperado:**

El estudiante podrá organizar, consultar y dar seguimiento a sus actividades académicas desde una sola plataforma.

## 3. Arquitectura tecnológica

### Frontend

* React 19: desarrollo de la interfaz de usuario.
* JavaScript: lenguaje principal del frontend.
* HTML: estructura de las páginas.
* CSS: estilos y diseño visual.
* React Router DOM 7: navegación entre páginas.
* Vite 8: servidor de desarrollo y compilación.
* ESLint 10: análisis estático del código.

### Backend

* PHP 8.2.12: lenguaje de programación del servidor.
* Laravel 12.69.3: framework para desarrollar la API.
* Laravel Sanctum: autenticación mediante tokens.

### Base de datos

* MariaDB 10.4.32, administrada mediante el entorno XAMPP.
* Base de datos del proyecto: `StudyHub`.

La estructura incluye tablas para usuarios, tokens de autenticación, recuperación de contraseñas, sesiones, caché y tareas en segundo plano.

### Herramientas de desarrollo

* Visual Studio Code: edición del código.
* XAMPP: entorno local para la base de datos.
* Composer: administración de dependencias de PHP.
* Node.js y npm: entorno de ejecución y administración de dependencias del frontend.
* Git: control de versiones local.
* GitHub: pendiente de configurar como repositorio remoto.

## 4. Estructura del proyecto

El proyecto se organiza de la siguiente manera:

* `backend/`: aplicación Laravel, API, autenticación, modelos, migraciones y pruebas.
* `frontend/`: aplicación React, componentes, estilos y navegación.
* `Sprints/`: documentación de los objetivos y avances de cada sprint.
* `.gitignore`: archivos y carpetas excluidos del control de versiones.

## 5. Configuración inicial de la base de datos

Se verificó la conexión entre Laravel y MariaDB mediante PDO.

También se confirmó la existencia de las tablas principales del sistema, entre ellas:

* `users`: usuarios y datos de seguridad.
* `password_reset_tokens`: recuperación de contraseñas.
* `personal_access_tokens`: tokens de autenticación.
* `migrations`: registro de las migraciones ejecutadas.
* `sessions`: almacenamiento de sesiones.
* `cache` y `cache_locks`: almacenamiento de caché.
* `jobs`, `job_batches` y `failed_jobs`: administración de tareas en segundo plano.

La tabla `users` contiene los campos necesarios para el registro, el perfil y el control progresivo de intentos fallidos de inicio de sesión.

## 7. Organización del desarrollo

El proyecto se desarrolla mediante la metodología Scrum, organizando las funcionalidades en sprints y utilizando un Product Backlog para establecer las prioridades.

Las funcionalidades se distribuyen en módulos como:

* Gestión de usuarios y perfiles.
* Gestión de materias y tareas.
* Fechas de entrega, prioridades y estados.
* Calendario académico.
* Búsqueda y filtros.
* Panel de control y estadísticas.
* Notificaciones.
* Diseño adaptable y modo oscuro.
* Seguridad, validaciones y pruebas.

La seguridad se considera un aspecto transversal que debe revisarse durante el desarrollo de las funcionalidades.
